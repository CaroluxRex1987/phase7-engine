Batch 1 follow-up: the four tests that imported engine_core unguarded

docs/PHASE7_NEXT.md has recorded this since batch 1 (dba1b63): converting
the suite's `if not _engine_available(): return` occurrences into real
pytest.skip() calls is how these four were found. They import
core.engine_core directly rather than going through that guard, so on a
machine without pandas_ta they failed outright instead of reporting
SKIPPED like the rest of the suite -- "reported for record, not fixed,"
since it was a defect in the four tests, not one of the audit's named
Criticals. Picked up now since nothing else is open on the roadmap.

THE FOUR, AND THE FIX FOR EACH

- tests/test_frame_ownership.py::test_the_engine_holds_no_caches
- tests/test_exit_model_removal.py::test_engine_core_has_no_render_parameter
- tests/test_imports.py::test_the_engine_and_the_fetcher_module_share_one_singleton

  All three are entirely about Phase7Engine/engine_core specifically --
  there is nothing left to check once pandas_ta is unavailable. Given the
  same `if not _engine_available(): pytest.skip(...)` guard every other
  pandas_ta-dependent test in the suite already uses.

- tests/test_imports.py::test_every_module_imports

  Different shape, different fix. This test imports all 21 ENGINE_MODULES
  looking for undefined names at module scope and bad import paths -- the
  class of bug this file's docstring cites seven real, logged incidents of.
  Only core.engine_core and indicators.indicators (and, it turns out,
  live_trading, transitively -- verified by running it, not assumed) import
  pandas_ta; the other ~18 modules do not. A blanket skip would have
  silently stopped checking all of them for a reason that has nothing to do
  with them.

  So this one is precise instead of blanket: a ModuleNotFoundError naming
  pandas_ta itself, exactly, and only when pandas_ta is demonstrably absent
  (checked once, not inferred from the exception), is recorded separately
  and does not fail the test. Every other module, and any OTHER exception
  from these pandas_ta-dependent modules -- including a real bug in either
  -- is still checked and still fails it. The names excused this way are
  printed to the test report rather than swallowed silently.

VERIFICATION

Ran the full suite twice: once in the existing sandbox (pandas_ta present)
and once in a brand-new virtualenv with pandas, numpy, matplotlib,
requests, colorama and pytest installed but pandas_ta deliberately absent.

  With pandas_ta:    137 passed, 0 skipped, 0 failed (unchanged from before
                      this patch)
  Without pandas_ta: 87 passed, 50 skipped, 0 failed, 0 errors -- previously
                      these four would have been counted among hard
                      failures/errors instead of skips. Confirmed
                      test_every_module_imports specifically still PASSES
                      (not skips) in this environment and its stdout names
                      exactly the three pandas_ta-dependent modules it
                      excused: "pandas_ta not installed; import not
                      verified for: core.engine_core, indicators.indicators,
                      live_trading" -- everything else in ENGINE_MODULES was
                      genuinely checked.

Golden snapshot unaffected: none of this touches engine code, only test
guards.

Not part of this patch: the "owed document batch" mentioned in the
roadmap's status diagram is still unscoped.
