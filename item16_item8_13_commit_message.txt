Item 8/13: report macro-timeframe failures as degradation

Roadmap step 6 (docs/PHASE7_NEXT.md), the last open item from the
independent audit.

THE DEFECT

engine_core.py fetched the macro timeframe, validated the frame, and on
failure left macro_bias at its initialised "NEUTRAL" -- without adding
anything to `degradation`. A failed higher-timeframe read and a genuinely
neutral macro trend rendered identically: same word on the panel, same
(missing) effect on confidence, same silent trust from every downstream
consumer of macro_bias (bias_engine's macro factor, signal_router's
macro/volume agreement check, decision_model's AGGRESSIVE-gate macro
checks). tests/test_golden_path.py::test_the_macro_series_is_actually_read
already documented this in its own docstring as "recorded rather than
fixed... a rider on sequence item 9's degrade ruling."

Two instances of the same shape, both fixed the same way:

1. core/engine_core.py -- the macro frame fails _validate_dataframe (a
   fetch error, or an insufficient/malformed frame). Previously fell
   through with macro_bias left at "NEUTRAL" and no record. Now appends a
   degradation naming the fetch error when data_fetcher recorded one
   (df_macro.attrs["fetch_error"], the same mechanism the base-data path
   already used), or a generic "invalid or insufficient" message otherwise.
2. core/engine_core.py -- add_technical_indicators raises while processing
   an otherwise-valid macro frame. Previously only logged a warning. Now
   also appends a degradation, same message shape as (1).

Ruled: report the failure like any other degraded input, per Viktor's item
9 "degrade, don't fabricate" ruling from 29 August. macro_bias still
cannot invent a direction from missing or unprocessable data, so it still
reports NEUTRAL either way -- but the run built on it is now marked
degraded (confidence capped, any directional action forced to
NO-TRADE (DEGRADED INPUT)), exactly like a failed ADX or SuperTrend
already was. Direction and whether a trade is allowed at all are otherwise
untouched -- this only makes an existing failure visible.

TESTS

- tests/test_golden_path.py::test_the_macro_series_is_actually_read:
  updated per its own docstring's note ("if engine_core has learned to
  report this failure honestly... this expectation should be updated to
  match"). Now checks both runs' `degradation` blocks: the full pinned set
  is not degraded, the set missing the macro CSV is degraded and names the
  macro timeframe in `missing_inputs`.
- tests/test_degraded_state.py: new
  test_a_macro_processing_exception_degrades_rather_than_fabricates,
  covering the second instance (an exception during macro processing,
  distinct from the fetch-failure case above). Uses a first-call-only
  monkeypatch of add_technical_indicators so the break lands on the macro
  frame only and base-data processing is untouched -- proving this is a
  degrade, not a halt, and that the base analysis is unaffected by a macro
  failure.

VERIFICATION

Python 3.12.3, numpy 2.2.6, pandas 3.0.5, pandas-ta 0.4.71b0. 137 items
(136 + 1 net new), 137 passed, 0 skipped, 0 failed. The golden snapshot did
NOT move and was not re-baselined: the pinned golden fixture always
includes a valid macro series, so neither new code path fires on it --

macro-processing-exception cases directly, not the golden fixture.

Not touched: nothing else on the roadmap is open after this. All six steps
