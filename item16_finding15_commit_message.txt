Audit Finding 15: pin dependency versions

requirements.txt and requirements-dev.txt listed bare package names with no
version constraints (pytest>=8.0 was the closest thing to a pin, and that's
a floor, not a pin). A fresh `pip install` could silently resolve a
different pandas / numpy / pandas_ta and shift indicator output -- this is
not hypothetical, it is exactly what happened across the 30 August Windows
reinstall (numpy moved from 1.26.4 to 2.2.6), caught only because someone
happened to check environment_before_reinstall.txt against the new install.

Pinned to the exact versions verified identical across both environments
that ran the full 137-test suite on 1 September 2026:

    pandas==3.0.5
    numpy==2.2.6
    matplotlib==3.11.1
    pandas_ta==0.4.71b0
    requests==2.32.5
    colorama==0.4.6
    pytest==9.1.1

Verification: created a brand-new virtualenv (nothing pre-installed),
`pip install -r requirements.txt -r requirements-dev.txt`, confirmed
`pip freeze` reports exactly these versions, then ran the full suite --
137 passed, 0 skipped, 0 failed, golden snapshot unmoved. This is the
cleanest verification of the three deliveries today: no leftover packages
from an accumulated sandbox environment, just what the pinned file itself
resolves to from empty.
