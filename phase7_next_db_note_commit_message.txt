Note a possible future database in PHASE7_NEXT.md

Viktor asked (1 September 2026) whether the project should eventually add
a database. Discussed conversationally rather than acted on: the current
flat-file logging (logs/phase7_decision_log_*.jsonl, phase7_state_*.json)
is fine for a single-user, single-machine tool that never executes trades,
and nothing today needs cross-run queries. If that changes -- wanting to
ask things like win rate by risk regime, or how often the item 14
AGGRESSIVE gate actually fires -- a lightweight embedded database (SQLite)
would be the natural fit as a query layer alongside the existing logs, not
a replacement for them.

Added a new "Not on the roadmap, worth revisiting" section recording this
so it isn't lost, without adding it to the actual suggested-order list --
no need has come up yet to act on it.

Documentation only -- no code or test changes, no suite run needed.
