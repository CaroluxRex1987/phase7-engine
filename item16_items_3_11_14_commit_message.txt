Item 16 remediation: rulings and fixes for items 3, 11, 14

Viktor delegated the trading-judgment rulings for these three items on

is each ruling and the code it produced.

Item 3 (Data Integrity) -- abnormal volume policy
--------------------------------------------------
Ruling: all-zero volume is rejected before analysis; an isolated extreme
spike is accepted at the validation layer (unchanged from the existing,
reasoned "not the validator's job" stance) but now degrades the run instead
of reaching every downstream score unflagged.

- data/validation.py: added a rejection for a series where every candle
  reports zero volume -- there is no genuine volume measurement to build
  VWMA or any volume-weighted read from, the same "nothing to salvage"
  reasoning this module already applies to negative prices. Non-finite
  volume was already covered by the existing NaN/Inf loop (volume is one of
  the five OHLCV columns it walks) -- the audit read the module's own
  comment as a narrower claim than the code actually makes.
- indicators/indicators.py: fixed the fallback the audit quoted directly --
  `np.where(valid_mask, price_volume_sum / volume_sum, close_prices)` awarded
  a fabricated zero-distance VWMA (worth 20 of 20 entry-quality points) for
  any rolling window with no usable volume. Now falls back to NaN, matching
  the "a VWMA that has no value has no value" rule already established one
  line below it. Also added isolated-volume-spike detection: a candle in the
  last VWMA_LENGTH window carrying more than 10x that window's median volume
  is recorded as a degradation (the spike's real value is never altered,
  only the run's confidence is capped).
- models/entry_model.py: fixed the second half of the same fabrication --
  `safe_float(df["VWMA"].iloc[-1], close)` substituted close price whenever
  VWMA was NaN, silently reintroducing the exact defect indicators.py just
  stopped producing. A missing VWMA now leaves entry quality's VWMA score at
  its existing neutral default (15/20) instead.
- tests/test_data_integrity.py: added test_rejects_all_zero_volume and
  test_accepts_an_isolated_volume_spike (the control -- a spike must NOT be
  rejected at this layer), plus the new case in
  test_each_defect_is_reported_by_its_own_name.

Item 11 (No Circular Reasoning) -- independent confirmation
-------------------------------------------------------------
Ruling: remove the duplicated factors rather than try to prove them
independent, since bias_score already is the one place all six weighted
factors are combined. Confidence and validation should each consume
evidence bias_score has not already consumed, and where none exists, should
not manufacture a second reading of the same evidence.

The independent audit (Finding 4) found the prior "sequence item 11" fix
incomplete: it removed a direct trend_health*0.3 term from confidence and
stopped seeding engine_core's validation score from trend_health, but left
two other duplications standing, plus a third internal to bias_engine.py.

- models/decision_model.py: _compute_confidence no longer computes
  structure_alignment (a bonus/penalty for structure_regime agreeing with
  bias -- structure_regime is already one of bias_engine's six weighted
  factors) or validation_adj (a bonus/penalty from risk.validation_state,
  itself built from macro_bias agreement and volume_sentiment strength --
  both already direct factors in bias_score). Confidence is now exactly
  bias_score's own magnitude. evaluate()'s `structure` parameter is removed
  along with its only remaining reader.
- indicators/trend_health.py: continuation_strength no longer includes a
  health_component derived from trend_health. It had exactly one consumer
  (bias_engine.py), which already weights trend_health directly at 0.30 --
  the health_component let the same measurement reach bias_score through a
  second of its six "independent" factors. No rescale: the honest ceiling
  without a health-derived term is lower (60, not 100).
- models/bias_engine.py: added an explicit dependency-graph comment listing
  where each of the six weighted factors comes from and what else reads it
  downstream, per the audit's required action ("document which values are
  derived from which upstream measurements").
- models/signal_router.py: updated the one call site for evaluate()'s
  dropped parameter; `structure` is still used for the decision object's own
  "structure" block, just not threaded into DecisionModel a second time.
- tests/test_no_circular_reasoning.py: rewritten. Kept the still-valid
  sequence-item-11 tests, updated the ones that hard-coded the now-removed
  structure/validation bonuses, and added tests that perturb structure_regime,
  macro/volume agreement, and continuation_strength independently -- the
  audit's own required verification.

Item 14 (independent risk decision) -- AGGRESSIVE/CONSERVATIVE labels
------------------------------------------------------------------------
Ruling: the labels survive, but "AGGRESSIVE" now requires an independent
risk-regime check, not just directional conviction and entry quality.
risk_model.classify_risk_regime() already computed a four-tier regime;
only the EXTREME-RISK-or-not boolean reached risk_valid, and the auditor's
concrete scenario (trend_health=80, entry_score=75, risk_valid=True,
volatility_state=HIGH VOLATILITY) showed AGGRESSIVE LONG being returned from
a regime classify_risk_regime would call HIGH VOLATILITY RISK.

- models/risk_model.py: validate_risk_parameters now returns the risk regime
  as a third value alongside (bool, reason). The three early-return branches
  (non-finite price/stop, invalid price/stop, stop distance out of bounds)
  return "UNKNOWN" for the regime, since classify_risk_regime is never
  reached and those branches already fail risk_valid regardless.
- core/engine_core.py: carries risk_regime from the updated call into the
  risk dict.
- core/decision_contract.py: RiskBlock declares the new risk_regime: str
  field.
- models/signal_router.py: the assembled decision object's risk block now
  includes risk_regime.
- models/decision_model.py: _determine_final_action reads risk_regime and
  requires it be outside ("HIGH VOLATILITY RISK", "EXTREME RISK") before
  returning an AGGRESSIVE label; a setup that would otherwise qualify
  instead returns the plain LONG/SHORT it earned on trend health and entry
  quality alone, with a reason naming the risk regime, not an absent
  position size. Direction and whether a trade is allowed at all are
  unchanged -- this gates intensity only.
- core/panel_render.py: added a RISK REGIME line so the new reasoning has
  something visible on the panel to point at.
- tests/test_no_risk_free_conviction.py (new): the audit's own verification
  list run directly -- high-conviction inputs across low/normal/high/extreme
  risk regimes (via classify_risk_regime, not hand-picked strings) and
  across wide/tight stops, confirming conviction alone cannot select
  AGGRESSIVE once the regime is elevated, on both the long and short side.
